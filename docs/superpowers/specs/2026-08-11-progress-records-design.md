# 체중 추세·활동 기록·주간 분석 설계

## 목표

사용자가 매일 체중을 부담 없이 기록하고, 하루 단위의 흔들림보다 7일 평균 추세를 중심으로 변화를 이해하게 한다. 같은 화면에서 식사·운동 완료 기록과 주간 달성률·XP를 확인하고, 기록된 사실에 한정한 주간 요약과 다음 주 행동 제안을 받는다.

## 제품 원칙

- 체중은 중요한 결과 지표지만 사용자의 가치나 캐릭터 성장 조건으로 사용하지 않는다.
- 일별 체중보다 7일 이동평균을 시각적으로 강조한다.
- 분석은 관찰된 데이터와 안전한 행동 제안을 분리해 표시한다.
- 기록이 부족하면 추측하지 않고 분석에 필요한 기록 수를 안내한다.
- 질병 진단, 목표 도달일 단정, 극단적 열량 제한, 보충제·약물 권고를 하지 않는다.
- AI 문구는 보상이나 처벌이 아니라 사용자의 자기조절을 돕는 설명이어야 한다.

## 과학적 근거와 제한

성인 체중 관리 연구에서는 규칙적인 자가 체중 측정이 자기조절 전략으로 연구되어 왔다. 일부 무작위 연구에서는 매일 체중 측정을 포함한 중재가 체중 관리 행동에 도움을 주었고, 해당 연구 모집단에서 뚜렷한 심리적 위해 증가가 관찰되지 않았다. 다만 이 결과를 모든 사람에게 일반화하지 않으며, 체중 측정이 불안이나 강박을 악화시키는 사용자는 빈도를 낮추거나 기능을 중단할 수 있어야 한다.

제품은 다음 자료를 근거 라벨에 연결한다.

- Steinberg et al., Daily Self-Weighing and Adverse Psychological Outcomes: https://pmc.ncbi.nlm.nih.gov/articles/PMC4157390/
- Steinberg et al., Weighing everyday matters: https://pmc.ncbi.nlm.nih.gov/articles/PMC4380831/
- Tracking Study의 동일 시간대 측정 지침: https://pmc.ncbi.nlm.nih.gov/articles/PMC6107396/
- CDC의 점진적 감량 안내: https://www.cdc.gov/healthy-weight-growth/losing-weight/index.html
- NIDDK Body Weight Planner의 성인 대상·의료 조언 제한: https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner

앱은 가능하면 기상 후 비슷한 조건에서 측정하도록 안내하지만 강제하지 않는다. CDC가 제시하는 주당 약 1–2파운드의 점진적 감량 범위는 안전 경고의 참고값으로만 사용한다. 개인별 적정 속도를 진단하지 않으며, 빠른 변화가 반복되면 의료 전문가 상담을 권한다.

### 포함

- 하루 한 건의 체중 기록
- 일별 체중선과 7일 이동평균선
- 이번 주 평균, 지난주 평균 대비 변화, 기록 일수
- 식사·운동 완료 달력
- 주간 계획 달성률과 획득 XP 요약
- 규칙 기반 주간 분석
- 다음 주 행동 제안 최대 2개
- 분석 근거와 안전 제한 표시
- 로컬 저장·복원과 손상된 기록의 부분 복구
- Today·Plan·Record 화면 내비게이션

### 제외

- 실제 생성형 AI API 호출
- 대화형 AI 코치
- 체중계·웨어러블 자동 동기화
- 사진 기반 식사 분석
- 의료 진단과 약물·보충제 추천
- 목표 체중 도달 날짜 예측
- 친구와 기록 공유
- 서버 동기화

## 핵심 사용자 흐름

1. 사용자가 기록 탭을 연다.
2. 오늘 체중을 kg 단위로 입력한다.
3. 그래프에서 일별 값과 강조된 7일 평균을 확인한다.
4. 이번 주 완료 달력과 달성률·XP를 확인한다.
5. 4일 이상의 체중 기록과 주간 행동 기록이 있으면 주간 분석을 읽는다.
6. 다음 주에 실천할 행동 제안 1~2개를 확인한다.
7. 잘못 입력한 체중은 날짜별 목록에서 수정하거나 삭제한다.

## 화면 구성

### 상단 입력

- 제목: `기록`
- 오늘 날짜
- `오늘 체중` 숫자 입력, 단위 `kg`
- 저장 후 `오늘 기록을 저장했어요.` 상태 메시지
- 이미 오늘 기록이 있으면 입력값을 채우고 버튼을 `수정하기`로 표시
- 보조 문구: `가능하면 비슷한 시간과 조건에서 측정해 주세요.`

### 체중 추세

- 최근 28일을 기본 범위로 표시
- 일별 체중: 가는 연한 하늘색 선과 작은 점
- 7일 이동평균: 굵은 진한 파란색 선
- 체중이 없는 날짜는 일별 선을 연결하지 않는다.
- 이동평균은 해당 날짜를 포함한 최근 7일 구간에서 기록이 4개 이상일 때만 계산한다.
- 그래프 위 요약: 현재 7일 평균, 이전 7일 평균 대비 kg 변화, 최근 7일 기록 수
- 값의 증가·감소를 성공·실패 색으로 표현하지 않는다.
- SVG 그래프에는 텍스트 요약과 접근 가능한 데이터 표를 함께 제공한다.

### 완료 달력

- 최근 4주를 주 단위 행으로 표시한다.
- 각 날짜에 식사 완료 수와 운동 완료 여부를 아이콘과 텍스트로 표시한다.
- 계획이 없던 날은 `계획 없음`, 계획했지만 미완료면 `미완료`, 완료하면 `완료`로 구분한다.
- 색상만으로 상태를 전달하지 않는다.

### 주간 요약

- 계획 식사 완료 수/전체 수
- 계획 운동 완료 수/전체 수
- 전체 달성률
- 이번 주 획득 XP
- 체중 기록 일수
- 완벽한 연속 기록 대신 주간 누적을 강조한다.

### 분석 카드

분석 카드는 다음 세 구역을 고정 순서로 보여준다.

1. `관찰된 사실`: 계산 결과만 기술한다.
2. `이번 주 해석`: 충분한 데이터가 있을 때만 완만한 추세·유지·변동성 증가를 설명한다.
3. `다음 주 한 가지씩`: 행동 제안 최대 2개를 제공한다.

`AI 분석`이라는 사용자용 라벨을 쓰되, 첫 버전은 검증 가능한 규칙 엔진임을 `분석 방식 보기`에서 명시한다. 실제 생성형 모델을 사용하지 않았다는 사실을 숨기지 않는다.

## 데이터 모델

```ts
interface WeightEntry {
  id: string
  date: string
  weightKg: number
  recordedAt: string
}

interface CompletionEvent {
  id: string
  date: string
  kind: 'planned-meal' | 'planned-activity' | 'recovery'
  plannedItemId?: string
  xpEarned: number
}

interface TrendPoint {
  date: string
  weightKg: number | null
  rollingAverageKg: number | null
}

interface WeeklyRecordSummary {
  weekStart: string
  plannedMeals: number
  completedMeals: number
  plannedActivities: number
  completedActivities: number
  completionRate: number | null
  xpEarned: number
  weightDays: number
}

interface WeeklyInsight {
  status: 'insufficient-data' | 'ready'
  observations: string[]
  interpretation: string | null
  suggestions: string[]
  evidenceIds: string[]
}
```

`WellnessState`에 `weightEntries`와 `completionEvents`를 선택 필드로 추가해 기존 version-1 저장 데이터와 호환한다. 날짜는 로컬 `YYYY-MM-DD`, 기록 시각은 ISO 날짜·시간 문자열로 저장한다.

## 계산 규칙

### 체중 기록

- 허용 범위는 20.0–350.0kg이다.
- 소수점 첫째 자리까지 저장한다.
- 같은 날짜의 새 기록은 기존 값을 대체한다.
- 삭제는 해당 날짜의 체중 기록만 제거한다.
- 저장 배열은 날짜 오름차순으로 정렬한다.

### 7일 이동평균

날짜 `d`의 평균은 `d`를 포함한 최근 7개 달력 날짜 안의 유효 기록으로 계산한다.

```text
rollingAverage(d) = sum(valid weights in d-6 ... d) / count(valid weights)
```

유효 기록이 4개 미만이면 `null`이다. 평균은 표시할 때 소수점 첫째 자리로 반올림하며 원본 체중 값은 변경하지 않는다.

### 주간 달성률

```text
completionRate = completed planned items / all planned items × 100
```

계획 항목이 0개면 `null`이며 0%로 표시하지 않는다. XP는 해당 주의 `CompletionEvent.xpEarned` 합계다.

## 규칙 기반 AI 분석

분석 입력은 최근 14일 체중, 현재·이전 주간 요약, 최근 완료 이벤트다. 다음 규칙은 위에서 아래 순서로 평가한다.

1. 최근 7일 체중 기록이 4일 미만이면 `insufficient-data`를 반환한다.
2. 현재 7일 평균과 이전 7일 평균이 모두 있어야 체중 추세를 설명한다.
3. 두 평균 차이의 절댓값이 0.2kg 미만이면 `평균 체중이 비슷하게 유지됐어요.`라고 표현한다.
4. 감소량이 주당 체중의 약 1%를 넘거나 CDC 참고 범위보다 빠른 변화가 2주 연속 관찰되면 원인을 단정하지 않고 `빠른 변화가 이어지면 의료 전문가와 상의해 주세요.`라고 안내한다.
5. 식사 또는 운동 달성률이 50% 미만이면 해당 영역의 계획 수를 늘리지 않고 `다음 주 계획을 한 단계 가볍게 조정`하도록 제안한다.
6. 달성률이 80% 이상이면 계획 강도를 자동으로 높이지 않고 현재 루틴 유지 또는 사용자가 원하는 한 가지 확장만 제안한다.
7. 제안은 최대 2개이며 체중 감량 속도를 높이기 위한 열량 삭감 수치를 만들지 않는다.

분석 결과는 템플릿과 수치 포맷터로 생성한다. 동일한 입력은 항상 동일한 결과를 내며 모든 관찰 문장은 계산 결과로 역추적할 수 있어야 한다.

## 컴포넌트와 경계

- `RecordsScreen`: 기록 화면 조합과 28일 범위 선택
- `WeightEntryForm`: 오늘 체중 입력·수정
- `WeightTrendChart`: SVG 선 그래프와 접근 가능한 표
- `CompletionCalendar`: 최근 4주 완료 상태
- `WeeklyRecordSummaryCard`: 주간 달성률·XP·기록 일수
- `WeeklyInsightCard`: 사실·해석·제안과 근거 안내
- `weight.ts`: 입력 검증, 날짜별 upsert/delete, 이동평균
- `records.ts`: 완료 이벤트와 주간 집계
- `insight.ts`: 결정적 분석 규칙
- `useWellnessGame`: 저장 명령과 완료 이벤트 생성

그래프 컴포넌트는 이동평균이나 안전 판단을 계산하지 않는다. 분석 모듈은 React, 브라우저 저장소, 생성형 AI API를 참조하지 않는다.

## 완료 이벤트 연동

- 계획된 식사·운동을 처음 완료할 때만 이벤트를 추가한다.
- 기존 중복 방지 이벤트 ID와 동일한 로컬 날짜 기준을 사용한다.
- 이미 완료한 항목을 다시 눌러도 XP와 완료 이벤트를 추가하지 않는다.
- 회복 퀘스트는 계획 항목이 없어도 날짜별 완료 이벤트를 남긴다.
- 기존 저장 데이터에는 과거 상세 이벤트가 없으므로 설치 이전 기록을 추정하지 않는다.

## 오류와 안전 처리

- 범위 밖 체중은 저장하지 않고 입력 옆에 오류를 표시한다.
- 손상된 `weightEntries`는 체중 기록만 초기화하고 계획·게임·캐릭터를 보존한다.
- 손상된 `completionEvents`는 완료 기록만 초기화하고 현재 주간 계획의 완료 상태를 보존한다.
- 날짜가 미래인 체중은 입력하지 못한다.
- 임신·수유 중, 18세 미만, 섭식장애 우려가 있는 사용자를 위한 의료적 판단을 앱이 대신하지 않는다.
- 사용자가 체중 기록을 불편하게 느끼면 그래프와 알림을 숨길 수 있다는 안내를 제공한다.

## 접근성

- 그래프 정보는 표와 요약 문장으로도 제공한다.
- 증가·감소·완료 상태를 색상에만 의존하지 않는다.
- 숫자 입력은 `inputMode="decimal"`, 명시적 kg 단위, 오류 연결을 사용한다.
- 날짜 셀과 동작 버튼은 최소 44px 터치 영역을 가진다.
- 키보드만으로 입력, 수정, 삭제, 근거 열기를 수행할 수 있다.
- 움직임 감소 설정에서는 그래프 선 등장 애니메이션을 제거한다.

### 시각 검증

- 체중 증가를 빨간색 실패 상태로 표현하지 않는다.
