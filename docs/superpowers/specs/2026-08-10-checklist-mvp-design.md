# 체크리스트 앱 1단계 MVP 설계

## 목표

개인 사용자가 로그인 없이 오늘의 할 일을 빠르게 추가하고, 완료하고, 우선순위를 파악하며, 하루의 진행률을 확인할 수 있는 로컬 우선 웹앱을 만든다. 첫 단계는 실제로 매일 사용할 수 있는 최소 기능에 집중하고 이후 수정, 필터, 마감일, 반복 습관, 통계, 계정 동기화를 단계적으로 추가할 수 있는 구조를 갖춘다.

## 범위

### 포함

- 오늘 할 일 추가, 완료 전환, 삭제
- 업무, 생활, 습관 분류
- 높음, 보통, 낮음 우선순위
- 미완료 우선 및 우선순위 기반 목록 정렬
- 전체 및 분류별 완료 현황
- 브라우저 로컬 저장과 새로고침 후 복원
- 데스크톱과 모바일 반응형 화면
- 키보드 조작, 명확한 포커스, 색상 외 상태 표현

### 제외

- 할 일 수정
- 필터와 사용자 지정 정렬
- 마감일, 메모, 하위 체크리스트, 태그, 알림
- 반복 습관과 연속 기록
- 주간·월간 통계
- 로그인, 계정, 여러 기기 동기화

## 기술 구성

- React와 TypeScript로 UI와 상태를 구현한다.
- Vite를 개발 및 빌드 도구로 사용한다.
- 앱의 저장 방식은 `TaskRepository` 인터페이스 뒤에 둔다.
- 1단계 저장 구현체는 `localStorage`를 사용한다.
- 서버 동기화 도입 시 UI와 핵심 로직을 바꾸지 않고 저장 구현체를 교체할 수 있게 한다.

## 화면 구조

데스크톱은 약 70:30 비율의 2열 레이아웃이다. 왼쪽은 오늘의 할 일, 오른쪽은 오늘의 흐름 패널이다. 모바일에서는 한 열로 전환해 할 일 목록 다음에 진행 패널을 배치한다.

### 상단 영역

- 현재 날짜
- 시간대에 맞춘 짧은 인사
- 오늘의 전체 완료율

### 빠른 추가

- 제목 입력
- 업무, 생활, 습관 분류 선택
- 높음, 보통, 낮음 우선순위 선택
- Enter 또는 추가 버튼으로 등록
- 빈 제목은 등록하지 않고 입력 영역에서 바로 안내한다.

### 할 일 목록

- 미완료 항목을 먼저, 완료 항목을 아래에 표시한다.
- 동일한 완료 상태 안에서는 높은 우선순위를 먼저 표시한다.
- 각 항목은 체크박스, 제목, 분류, 우선순위, 삭제 동작을 제공한다.
- 완료 상태와 분류는 색상뿐 아니라 텍스트, 아이콘, 취소선 등으로도 구분한다.
- 빈 목록에는 “오늘의 첫 장면을 만들어보세요”라는 안내와 강조된 입력 영역을 보여준다.

### 오늘의 흐름 패널

- 원형 전체 진행률
- 완료 수와 전체 수
- 업무, 생활, 습관별 완료 수와 전체 수
- 실제 저장된 할 일만 집계하며 꾸며낸 성과나 사용자 수는 표시하지 않는다.

## 시각 방향: 빛으로 흐르는 하루

시간의 변화가 무대 뒤편의 사이클로라마 조명처럼 화면 분위기에 반영된다.

- 새벽: 짙은 검정과 코발트
- 아침: 코발트에서 옅은 장밋빛으로 전환
- 낮: 밝고 깨끗한 중성 배경
- 저녁: 어두운 남색과 절제된 따뜻한 빛
- 배경 변화는 장식층에 제한하고 콘텐츠 표면과 텍스트는 항상 충분한 대비를 유지한다.
- 움직임 감소 설정에서는 배경 전환과 완료 애니메이션을 최소화한다.
- 완료 동작은 짧고 부드럽게 표현하되 생산성 도구의 즉각성을 해치지 않는다.

## 컴포넌트 경계

- `AppShell`: 시간대 테마와 전체 레이아웃
- `TodayHeader`: 날짜, 인사, 전체 진행률 요약
- `QuickAddForm`: 입력 검증과 추가 요청
- `TaskList`: 정렬된 목록과 빈 상태
- `TaskItem`: 완료 전환과 삭제 요청
- `ProgressPanel`: 전체 및 분류별 집계 표시
- `useTasks`: 할 일 상태와 저장소 연동
- `TaskRepository`: 저장소 계약
- `LocalStorageTaskRepository`: 직렬화, 역직렬화, 저장 오류 처리

컴포넌트는 저장소를 직접 호출하지 않는다. 사용자 동작은 `useTasks`를 거쳐 상태와 저장소에 반영된다.

## 데이터 모델

```ts
type TaskCategory = 'work' | 'life' | 'habit'
type TaskPriority = 'high' | 'medium' | 'low'

interface Task {
  id: string
  title: string
  completed: boolean
  category: TaskCategory
  priority: TaskPriority
  createdAt: string
}
```

ID는 브라우저의 `crypto.randomUUID()`로 생성하고 생성 시각은 ISO 8601 문자열로 저장한다.

## 데이터 흐름

1. 앱 시작 시 `useTasks`가 저장소에서 목록을 불러온다.
2. 추가 요청은 제목을 정규화하고 검증한 뒤 새 `Task`를 만든다.
3. 완료와 삭제 요청은 메모리 상태에 반영한 뒤 저장한다.
4. 화면의 정렬 목록과 진행률은 저장된 상태에서 계산한다.
5. 새로고침하면 동일한 저장소 데이터로 상태를 복원한다.

## 오류 처리

- 저장된 JSON이 손상됐거나 스키마가 유효하지 않으면 해당 값을 사용하지 않고 빈 목록으로 시작한다.
- 복구가 발생하면 사용자가 원인을 알 수 있도록 비차단 안내를 표시한다.
- 저장 실패 시 현재 메모리 상태와 입력값을 유지하고 오류 안내 및 재시도 수단을 제공한다.
- 예상치 못한 렌더링 오류는 앱 전체가 빈 화면이 되지 않도록 오류 경계에서 처리한다.

## 접근성

- 모든 주요 동작은 키보드만으로 수행할 수 있다.
- 체크박스와 버튼에는 이해 가능한 접근성 이름을 제공한다.
- 포커스 링은 모든 시간대 테마에서 명확히 보인다.
- 상태와 우선순위는 색상만으로 전달하지 않는다.
- 최소 터치 영역과 읽기 쉬운 본문 크기를 유지한다.
- `prefers-reduced-motion`을 존중한다.

## 테스트와 완료 기준

### 단위 테스트

- 제목 정규화와 빈 입력 거부
- 미완료/완료 및 우선순위 정렬
- 전체 및 분류별 진행률 계산
- 저장 데이터 검증과 손상 데이터 복구

### 통합 테스트

- 할 일을 추가하면 목록과 진행률이 갱신된다.
- 완료 전환 후 정렬과 집계가 갱신된다.
- 삭제 후 목록과 집계가 갱신된다.
- 새로고침에 해당하는 재초기화 후 데이터가 복원된다.
- 저장 실패 시 사용자 데이터가 화면에서 사라지지 않는다.

### 시각 및 접근성 검증

- 모바일과 데스크톱에서 레이아웃이 깨지지 않는다.
- 각 시간대 테마에서 텍스트와 포커스 대비가 유지된다.
- 키보드만으로 추가, 완료, 삭제가 가능하다.
- 움직임 감소 설정에서 불필요한 전환이 제거된다.

## 후속 단계

1. 수정, 필터, 정렬, 마감일과 사용성 강화
2. 반복 습관, 연속 기록, 오늘의 습관 처리
3. 주간·월간 통계와 영역별 균형 보기
4. 저장소 구현체 확장과 계정·동기화
