# 주간 식단·운동 계획 설계

## 목표

일반 사용자가 복잡한 캘린더 편집 없이 자신의 식사 횟수와 운동 가능 횟수에 맞는 7일 계획을 자동으로 받고, 필요한 항목만 요일 이동 또는 대안 교체로 수정하게 한다.

## 범위

### 포함

- 하루 2끼·3끼·4끼 설정
- 원하는 끼니를 스무디로 지정
- 주 2회·3회·4회·5회 운동 횟수 설정
- 헬스장 머신·맨몸 홈트·산보 선호 비율
- 월요일부터 일요일까지 기본 계획 자동 생성
- 식사와 운동의 다른 요일 이동
- 운동의 같은 목적 대안 교체
- 하루 상세에서 식사 분량과 운동 동작 확인
- 오늘 화면과 완료 상태 연동
- 로컬 저장과 복원
- 모바일 세로 일정과 데스크톱 7일 보드

### 제외

- 드래그 앤드 드롭
- GPS와 스마트워치 연동
- 기록에 따른 완전 자동 재계획
- 스무디 외 레시피 자동 생성
- 친구와 계획 공동 편집
- 서버 동기화

## 핵심 흐름

1. 사용자가 식사 횟수, 스무디 끼니, 운동 횟수와 환경 비율을 정한다.
2. 앱이 7일 계획을 생성한다.
3. 사용자는 주간 요약과 날짜별 계획을 확인한다.
4. 수행하기 어려운 항목을 다른 요일로 이동하거나 대안으로 교체한다.
5. 오늘 날짜의 계획이 기존 오늘 화면에 표시된다.
6. 오늘 화면에서 완료한 상태가 주간 계획에도 반영된다.

## 화면 구성

### 계획 설정

- 식사 횟수: 2·3·4끼 중 하나
- 스무디 끼니: 아침·점심·저녁·간식에서 복수 선택
- 운동 횟수: 주 2~5회
- 운동 환경: 헬스장·집·산보 비율
- “이번 주 계획 만들기” 기본 동작

### 주간 요약

- 계획된 식사 수
- 스무디 식사 수
- 운동 횟수와 환경별 분포
- 완료 수와 전체 수
- 계획 다시 만들기

### 날짜별 계획

모바일에서는 날짜별 세로 카드로 표시한다. 데스크톱에서는 동일 데이터를 7개 날짜 열로 배치한다. 각 날짜는 식사와 운동을 시간순으로 보여준다.

각 항목은 다음 동작을 제공한다.

- 상세 보기
- 다른 날짜로 이동
- 대안으로 교체
- 완료 상태 확인

### 이동과 교체

날짜 이동은 목적 날짜를 고르는 작은 시트로 제공한다. 이미 같은 식사 슬롯이나 운동이 존재하면 중복을 알리고 이동하지 않는다.

운동 교체는 헬스장·홈트·산보 중 같은 날 수행 가능한 대안을 보여준다. 정확한 열량 동등성을 주장하지 않고 예상 시간과 체감 강도를 표시한다.

## 데이터 모델

```ts
type MealSlot = 'breakfast' | 'lunch' | 'dinner' | 'snack'

interface WeeklyPlanPreferences {
  mealsPerDay: 2 | 3 | 4
  smoothieSlots: MealSlot[]
  activitiesPerWeek: 2 | 3 | 4 | 5
  activityMix: {
    gym: number
    home: number
    walk: number
  }
}

interface PlannedMeal {
  id: string
  date: string
  slot: MealSlot
  kind: 'smoothie' | 'regular'
  smoothieItems?: SmoothieItem[]
  completed: boolean
}

interface PlannedActivity {
  id: string
  date: string
  templateId: string
  completed: boolean
}

interface WeeklyPlan {
  id: string
  weekStart: string
  preferences: WeeklyPlanPreferences
  meals: PlannedMeal[]
  activities: PlannedActivity[]
}
```

모든 날짜는 사용자의 로컬 시간대 기준 `YYYY-MM-DD` 문자열로 저장한다. 주 시작일은 월요일이다.

## 자동 생성 규칙

- 선택한 식사 횟수에 따라 매일 동일한 기본 슬롯을 만든다.
- 사용자가 지정한 슬롯은 스무디, 나머지는 일반식으로 설정한다.
- 운동은 주간 횟수만큼 날짜 간 간격을 우선해 분산한다.
- 환경별 개수는 사용자가 입력한 비율을 가장 가까운 정수 분포로 변환한다.
- 같은 날짜에 운동을 두 개 생성하지 않는다.
- 운동 가능 날짜 정보가 없는 첫 버전에서는 월·수·금·토·화 순으로 배치한다.
- 스무디 기본 분량은 기존 계산기의 현재 조합을 복사하며 변경 후 영양 합계를 다시 계산한다.

## 컴포넌트와 경계

- `WeeklyPlanScreen`: 설정 또는 생성된 계획 화면 전환
- `PlanPreferencesForm`: 식사·운동 선호 입력
- `WeeklySummary`: 주간 집계
- `WeekBoard`: 반응형 날짜 목록
- `DayPlanCard`: 하루 식사·운동
- `PlanItemActions`: 이동·교체 동작
- `generateWeeklyPlan`: 순수 자동 생성 함수
- `movePlannedItem`: 중복 검사 후 날짜 이동
- `replacePlannedActivity`: 템플릿 교체
- `calculateWeeklySummary`: 주간 집계
- `useWellnessGame`: 계획 저장과 오늘 화면 연동

화면 컴포넌트는 날짜 분산이나 중복 규칙을 직접 구현하지 않는다.

## 오류 처리

- 설정값의 운동 환경 합계가 0이면 계획을 생성하지 않고 안내한다.
- 이동 대상 날짜에 동일 슬롯이나 운동이 있으면 충돌 메시지를 표시한다.
- 저장 실패 시 화면의 수정 상태를 유지하고 재시도할 수 있게 한다.
- 저장 데이터가 손상되면 기존 일일 데이터는 보존하고 주간 계획만 초기화한다.
- 존재하지 않는 운동 템플릿은 산보 기본 템플릿으로 대체하고 안내한다.

## 접근성

- 날짜와 완료 상태를 색상만으로 구분하지 않는다.
- 모든 이동·교체 동작은 키보드로 수행할 수 있다.
- 모바일 터치 대상은 최소 44px이다.
- 시트가 열리면 포커스를 내부로 이동하고 닫힌 뒤 원래 버튼으로 돌려보낸다.
- 움직임 감소 설정에서는 날짜 이동 전환을 제거한다.

## 테스트와 완료 기준

### 단위 테스트

- 식사 횟수별 슬롯 생성
- 스무디 슬롯 적용
- 주 2~5회 운동 날짜 분산
- 환경 비율의 정수 분포
- 날짜 이동 중복 거부
- 운동 대안 교체
- 주간 완료 집계

### 통합 테스트

- 설정 제출 후 7일 계획이 나타난다.
- 항목 이동 후 원래 날짜와 대상 날짜가 함께 갱신된다.
- 운동 교체 후 상세 동작이 변경된다.
- 오늘 계획 완료가 주간 계획에 반영된다.
- 새로고침 후 계획과 완료 상태가 복원된다.
- 저장 실패 시 화면에서 변경 내용이 사라지지 않는다.

### 시각 검증

- 390px에서 날짜 카드가 한 열로 표시되고 수평 오버플로가 없다.
- 1024px 이상에서 7일 보드가 읽을 수 있는 밀도로 표시된다.
- 밝은 아이보리·하늘색 시각 체계를 유지한다.
- 게임 표현은 완료 보상에만 사용한다.
